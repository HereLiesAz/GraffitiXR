# GraffitiXR

GraffitiXR — Android-приложение для уличных художников. Существует множество приложений, которые накладывают изображение на изображение с камеры, чтобы вы могли виртуально отслеживать его, но когда я рисую фреску на основе эскиза, который я сохранил на своем телефоне, использование штатива действительно может ослабить поток. Мы повсюду, черт возьми. Я кладу телефон в карман. Даже приложения, которые используют AR, чтобы изображение было стабильным и в одном месте, не могут справиться с ужасной темнотой кармана.

Итак, я делаю что-то лучше, перепрофилируя (как называют это знающие люди) метод сетки. Я всегда думал: «Почему нельзя сохранить эти конкретные рисунки, как постоянную привязку, чтобы наложение всегда было просто в нужном месте?»

Итак, вот что делают эти каракули.

Мне пришлось изобрести собственный **фингерпринтовый релокализатор**, который работает на Android без помощи облака — потому что граффити, как вы знаете, незаконно. Когда вы фиксируетесь на стене, приложение снимает OpenCV-«отпечаток» (**fingerprint**) ваших меток — дескрипторы плюс горстку триангулированных 3D-точек. Даже после потери отслеживания или выключения экрана движок сверяет живую картинку с камеры с этим отпечатком и решает задачу позиционирования (PnP), чтобы **мгновенно вернуться** на место и заново выровнять фреску по стене за миллисекунды — без облака и без предварительного сканирования всей комнаты.

И я последовал за этим тем, что называю **телеологическим SLAM**: поскольку мы знаем, каким должен получиться результат, я использую OpenCV, чтобы следить за вашим прогрессом — а это значит, что чем дальше вы продвигаетесь, тем плотнее наложение прилипает к стене. Без этого вы бы закрыли эти отметки самой картиной, что со временем делало бы приложение только менее точным. Именно здесь другие подобные приложения действительно терпят неудачу.

И «снап-бэк», и самодополняющийся отпечаток пока поставляются как опциональный переключатель (Настройки > диагностический оверлей, по умолчанию выключен), пока я не проверю их на реальном железе, — так что не ждите, что оба будут работать «из коробки» прямо сейчас.

Просто ради забавы я также включил не-AR функцию наложения изображения для трассировки — как это делают другие приложения, — на случай, если вам так удобнее. А если вам совсем не до строгостей, есть режим **Mockup**. Сфотографируйте стену — и у меня найдётся пара быстрых инструментов для быстрого макета. А если вам нечего доказывать и вы просто хотите идеально скопировать изображение на бумагу, режим **Trace** позволяет использовать телефон как лайтбокс: экран остаётся включённым на максимальной яркости, изображение зафиксировано на месте, а все касания блокируются, пока вы не закончите.

А ещё есть приличный набор инструментов дизайна для подготовки того самого одного изображения, которое вы переносите на стену, — тон, цветовой баланс, выделение контуров, изоляция объекта. Совмещение нескольких изображений в одно — задача компаньон-приложения для дизайна, а не этого приложения. Я мог бы продолжать, но, кажется, уже и так наговорил достаточно.

## Ключевые особенности
*   **Автономность (Offline-First):** ни для чего в приложении не нужно облако — отслеживание, рендеринг и работа над дизайном происходят полностью локально. Единственное, что вообще может покинуть устройство, — отчёт о сбое, и он отправляется только по вашему явному согласию, по умолчанию выключен (Настройки > Отчёты о сбоях); см. [`docs/ru/PRIVACY_POLICY.md`](PRIVACY_POLICY.md).
*   **Фингерпринт-релокализация:** нативный C++17-конвейер на OpenCV (дескрипторы ORB/SuperPoint + PnP/RANSAC) снимает «отпечаток» меток, которые вы наносите на стену, и возвращает наложение на место после потери отслеживания — полностью офлайн, без предварительного сканирования помещения.
*   **Готовность к «карману» (экспериментально, по умолчанию выключено):** коррекция дрейфа и самодополняющийся отпечаток (чтобы «снап-бэк» переживал закрашивание исходного эталона) уже существуют и включаются в Настройки > диагностический оверлей, но пока не проверены на реальных устройствах — см. [Teleological SLAM](../TELEOLOGICAL_SLAM.md).
*   **Учёт двух объективов:** на устройствах, где есть аппаратный стереодепс, приложение выбирает его автоматически; на остальных устройствах отслеживание идёт через монокулярную позу ARCore без отдельной оценки глубины.
*   **Режим Co-op:** зашифрованный, парный по QR-коду обмен сеансом, чтобы соавтор мог наблюдать за живым холстом хоста в AR. Пока работает только в направлении хост → гость — правки гостя пока не синхронизируются обратно.
*   **Интерфейс AzNavRail:** навигация одним большим пальцем, рассчитанная на художника с баллончиком в руке.

## Режимы
*   **AR-фреска (AR Mural):** основной точный инструмент для привязки цифровых концепций к физическим поверхностям, отслеживаемый через фингерпринт-релокализатор, описанный выше.
*   **Режим Mockup:** быстрые инструменты для визуализации слоёв и режимов наложения поверх статичных фотографий стены.
*   **Trace (лайтбокс):** экран на полной яркости для копирования на бумагу с блокировкой касаний, автоскрытием панели и выходом по громкости (вверх, вниз, вверх, вниз).
*   **Overlay:** не-AR трассировка изображения — ваше референсное изображение накладывается на живую картинку с камеры (CameraX) с регулируемой прозрачностью. На небольшом числе устройств без ARCore этот режим вместо этого может отслеживать форму, которую вы отмечаете на стене, тем же конвейером на OpenCV — только в плоскости.
*   **Design:** инструменты размещения и читаемости для того самого одного изображения дизайна, которое вы переносите, — прозрачность/яркость/контраст/насыщенность/цветовой баланс, инверсия, выделение контуров и изоляция объекта. Изображение дизайна ровно одно; совмещение нескольких изображений в одно — задача компаньон-приложения для дизайна, а не этого приложения.

## Лицензирование
GraffitiXR распространяется по модели **source-available, а не open source.** Приложение, модули `core:*` и движок AR / SLAM / телеологической подсистемы лицензированы по **PolyForm Noncommercial 1.0.0** ([`/LICENSE`](../../LICENSE)); заявленная поверхность API для расширений и импортёры ассетов — по лицензии **MIT** ([`docs/licenses/MIT.txt`](../licenses/MIT.txt)). **Скомпилированное приложение бесплатно для любого использования, включая платные заказы** — условие «не для коммерческого использования» относится к повторному использованию *исходного кода*, а не к художникам, выполняющим оплачиваемую работу. Подробную, авторитетную раскладку по путям и приоритетам см. в [`docs/LICENSING.md`](../LICENSING.md). Сторонние библиотеки (OpenCV, ML Kit и др.) сохраняют собственные исходные лицензии.

## Архитектура
Строго разделённая, многомодульная Clean Architecture:
*   `:app` — навигация, оркестрация камеры и внедрение зависимостей Hilt.
*   `:feature:ar` — управление сессией ARCore, `ArRenderer` и обработка данных SLAM.
*   `:feature:editor` — работа с одним изображением дизайна и его коррекциями.
*   `:feature:dashboard` — библиотека проектов, онбординг и настройки.
*   `:core:nativebridge` — нативный движок на C++ (`MobileGS`), JNI-мост и потоки релокализации. Сам OpenCV — это зависимость из Maven Central (`org.opencv:opencv`), а не встроенный модуль.
*   `:android_collaboration_module` — одноранговая (peer-to-peer) сеть для режима Co-op (хост → гость; см. «Ключевые особенности» выше).
*   `:core:data` / `:core:domain` / `:core:common` — единый слой данных и абстракция для носимых устройств.
*   `:core:design` — общая дизайн-система на Compose (переиспользуемые элементы управления и оверлеи).
