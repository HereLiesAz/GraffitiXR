# GraffitiXR

GraffitiXR 是一款为街头艺术家设计的 Android 应用程序。有很多应用程序可以在您的相机视图上叠加图像以便您进行虚拟描摹，但是当我在手机上保存的草图基础上绘制壁画时，使用三脚架真的很破坏节奏。我们到处走动。我呢，我把手机放在口袋里。即使是使用 AR 保持图像稳定在原位的应用程序也无法应对口袋里无尽的黑暗。

因此，我通过重新利用（内行人称之为）网格方法来制作更好的东西。我一直在想："为什么不能像持久锚点一样保存这些特定的涂鸦，以便覆盖层始终准确地位于正确的位置？"

所以，现在，这就是那些涂鸦的作用。

我不得不发明一个无需借助云端即可在 Android 上运行的自定义**指纹重定位器（fingerprinted relocalizer）**——因为涂鸦，你知道的，是非法的。当你锁定一面墙时，它会捕获你笔迹的 OpenCV 特征**指纹**——描述符加上少量经过三角测量的 3D 点。即使在跟踪丢失或屏幕关闭之后，引擎也会将实时摄像头画面与该指纹进行匹配，并求解姿态（PnP），在几毫秒内**瞬间归位**，将你的壁画重新对齐到墙上——无需云端，也无需预先扫描整个房间。

我接着使用了我称之为"目的论 SLAM"的技术——因为我们知道结果应该是什么样子，所以我使用 OpenCV 来查看您的进度，这意味着您进行的越深入，覆盖层与墙壁的贴合度就越高。如果没有这个，您将用画作本身掩盖那些标记，使应用程序在您进行过程中变得越来越不准确。这正是其他类似应用程序真正失败的地方。

上述两项功能——瞬间归位（snap-back）和自我扩展指纹（self-extending fingerprint）——目前都是作为一个默认关闭的选择性开关（设置 > 诊断叠加层）随应用发布的，因为我还在真实硬件上验证它们，所以目前请不要指望这两项功能开箱即用。

只是为了好玩，我包含了非 AR 图像叠加功能来进行图像描摹，就像您使用那些其他应用程序一样，以防您喜欢那种方式。或者，如果您非常疯狂，还有**效果图模式（Mockup mode）**。拍一张墙壁的照片，然后我提供了一些用于快速制作效果图的快速工具。并且如果您无须证明什么，您只是想完美地将某些内容复制到纸上，**透写台模式（Trace mode）**允许您将手机用作透写台，保持屏幕常亮并调高亮度，将您的图像锁定到位并阻止所有触摸，直到您完成。

然后，还有一套不错的设计工具，用于在将单张图像贴到墙上之前对其进行准备。我可以继续说下去，但我觉得我已经说得够多了。

## 主要特点
*   **离线优先：** 应用所做的一切都没有云端依赖——追踪、渲染和设计工作都在本地完成。唯一会离开设备的东西是崩溃报告，而且它是选择性开启的，默认关闭（设置 > 崩溃报告）；详见 [`docs/zh/PRIVACY_POLICY.md`](docs/zh/PRIVACY_POLICY.md)。
*   **指纹重定位（Fingerprint Relocalization）：** 一个 C++17 原生 OpenCV 管道（ORB/SuperPoint 描述符 + PnP/RANSAC），对你在墙上绘制的标记进行指纹识别，并在跟踪丢失后使覆盖层瞬间归位——完全离线，无需预先扫描房间。
*   **口袋就绪（实验性，默认关闭）：** 存在漂移校正和自我扩展指纹功能（使瞬间归位能在原始参照被涂盖后依然生效），可在设置 > 诊断叠加层中开启，但两者都尚未在真实硬件上得到验证——参见[目的论 SLAM](docs/TELEOLOGICAL_SLAM.md)。
*   **双镜头感知：** 在支持硬件立体深度的设备上自动选用它；其他设备则通过 ARCore 的单目姿态进行追踪，没有独立的深度估计。
*   **协作模式（Co-op Mode）：** 加密的、通过二维码配对的会话共享，让协作者可以在 AR 中观看主持人的实时画布。目前仅支持主持人 → 访客的单向模式——访客自己的编辑还不会同步回去。
*   **AzNavRail 界面：** 拇指驱动的单手导航，专为手持喷漆罐的艺术家设计。

## 模式
*   **AR 壁画：** 将数字构想锚定到物理表面的核心精确工具，由上述指纹重定位器进行追踪。
*   **效果图模式：** 用于在静态墙面照片上可视化图层和混合模式的快捷工具。
*   **透写台（Trace）：** 全亮度表面，用于在纸上描摹，具备触摸锁定、导航栏自动收起，以及物理音量键退出（上、下、上、下）。
*   **叠加（Overlay）：** 非 AR 图像描摹——你的参照图像叠加在实时摄像头画面（CameraX）上，透明度可调。在少数没有 ARCore 的设备上，此模式可以改为使用同一个 OpenCV 管道追踪你在墙上标记的形状，仅限平面追踪。
*   **设计（Design）：** 对单张图像进行编辑和准备——混合模式、透明度/颜色调整，以及轮廓提取——为将其贴到上述任一模式之前做准备。

## 架构
严格解耦的多模块整洁架构：
*   `:app` — 导航、相机编排，以及 Hilt 依赖注入。
*   `:feature:ar` — ARCore 会话管理、`ArRenderer`，以及 SLAM 数据处理。
*   `:feature:editor` — 单张图像的处理与调整。
*   `:feature:dashboard` — 项目库、引导流程与设置。
*   `:core:nativebridge` — 原生 C++ 引擎（`MobileGS`）、JNI 桥接，以及重定位线程。OpenCV 本身是一个 Maven Central 依赖（`org.opencv:opencv`），不是一个内置模块。
*   `:android_collaboration_module` — 协作模式的点对点网络（主持人 → 访客；见上文"主要特点"）。
*   `:core:data` / `:core:domain` / `:core:common` — 统一的数据层与可穿戴设备抽象层。
*   `:core:design` — 共享的 Compose 设计系统（可复用控件与叠加层）。
