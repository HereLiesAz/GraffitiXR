# GraffitiXR codebase audit — squash list

Full read-only audit across all modules (app, core:*, feature:*, collab, native C++). No `TODO`/`FIXME`
markers exist — every item below is a *silent* stub, unwired path, or bug found by reading the logic.
`[ ]` = open, `[x]` = fixed. Grouped by severity; "Decisions needed" holds the design-dependent ones.

Verification for the current pass: `./gradlew testDebugUnitTest` (413 tests),
`:core:nativebridge:externalNativeBuildDebug`, `detekt`, and `assembleDebug` all pass. Nothing here
was verified on a device — this environment has none, so every behavioural claim is reasoned from
the code and, where possible, pinned by a unit test.

## HIGH — crash / security / data-loss / ANR / OOM

- [x] **AR overlay teleports to world origin on tracking loss.** `feature/ar/anchor/AnchorOrchestrator.kt:72` — `getConsensusMatrix()` returned IDENTITY when no anchor is TRACKING → jumps to origin on any brief tracking loss. ✅ holds the last-good matrix; also synchronized all shared state (GL vs main thread) per PR review.
- [x] **Main-thread native map-save → ANR.** `app/MainActivity.kt:1191`. ✅ `withContext(Dispatchers.IO)`.
- [x] **Save-race: wall-feature-map vs editor save (data-loss).** ✅ both now funnel through the repository's atomic `updateProject { transform }`.
- [x] **Zip-bomb OOM (import + spectator).** ✅ bounded `readEntryBounded()` streaming, aborts mid-stream.
- [x] **Zip-bomb OOM (.azp install).** ✅ streams with a 64 MB cumulative cap (`MAX_PACKAGE_BYTES`).
- [x] **Fast-stroke data-loss.** ✅ the fallback rasterises the collected points before committing.
- [x] **Concurrent-mutation crash mid-stroke.** ✅ all access routes through `synchronized(strokeCollectedPointsLock)`.
- [x] **JNI fingerprint-restore OOB read.** ✅ both paths bounds-check the descriptor blob before building the `cv::Mat`.
- [x] **Untrusted co-op parser overflow crash.** ✅ 64-bit length math, header sanity checks, bounds validation before allocation.
- [x] **AR map autosave never ran, for the whole life of every session.** `feature/ar/ArViewModel.kt` — `saveMapNow()` early-returned on `slamManager.getSplatCount() <= 0`, and `startAutoSave()`'s 30 s loop only fired when that count moved. `MobileGS::getSplatCount()` has been a hardcoded `return 0` since the voxel/splat map was deleted, so the guard was permanently true and the loop permanently idle: the accumulated ARCore point cloud and the wall feature map were persisted *only* by the explicit saves on AR exit and app background, and a crash or a kill in between lost everything scanned since. ✅ both now key on `ArRenderer.mappedPointCount` (the live accumulated cloud). `loadMapIfExists()` lost the same dead guard and the no-op `loadModel`, and `ArRenderer`'s perception-cache `mapGrew` — which read the same hardcoded zero and so was permanently false — now reads the cloud too.
- [x] **A normal large edit tore down the co-op session.** `collab/session/DeltaBuffer.kt` + `HostSession.enqueueOp` — the replay buffer refused anything over its 5 MB / 1000-op cap, and `enqueueOp` treated a refusal as fatal. Two routine ways to hit it: one `Op.LayerBitmapReplace` carries a full-canvas PNG (a single Liquify warp or bitmap undo exceeded the whole budget on its own), and the buffer is trimmed only by a guest's DELTA_ACK — so an artist who started sharing and kept working while *waiting* for a guest filled it and disconnected themselves before anyone joined, for a replay history a first-time guest never uses. ✅ the buffer now degrades instead of failing: a newer full-layer `LayerBitmapReplace` supersedes earlier buffered ops for that layer, the cap is sized for whole-canvas PNGs, and genuine overflow evicts oldest-first and records a gap. `opsAfter` returns null inside a gap, and `handleConnection` answers that with a fresh bulk snapshot — the path a first-time guest already takes. 11 new `DeltaBufferTest` cases pin the contract.
- [x] **Co-op silently dropped every guest edit.** `collab/OpEmitterImpl.kt` → `CollaborationManager.enqueueHostOp` no-op'd whenever `hostSession` was null, which as a guest is always: the edit applied locally, reached nobody, and the two canvases diverged with neither end told. The protocol is host-broadcast and has no guest→host channel, which is a real limitation — but silence is not how to state it. ✅ the manager now signals `guestEditDropped` (conflated, so a gesture's burst of ops reports once) and `ArViewModel` surfaces it once per session as "You're viewing the host's project — your changes stay on this device". The read-only affordances that already existed (spectator banner, blocked canvas gestures) are unchanged.

## Native — the vestigial voxel/splat layer

- [x] **~20 native functions were no-op / `0` / `null` / `false` stubs**, and Kotlin still called them and gated real behaviour on the results. ✅ removed end to end — `MobileGS` members, JNI entry points, `SlamManager` wrappers and every call site: `saveModel`, `loadModel`, `importModel3D`, `clearMap`, `pruneByConfidence`, `setVoxelSize`, `setParallaxMinDegrees`, `draw`, `drawDebugLayers`, `drawCoverage`, `initGl`/`resetGlContext`/`initVoxelGl`/`initVoxelGlProgram`/`initVoxelGlBuffer`/`initMeshGl`, `pushPointCloud`/`feedPointCloud`, `processDepthFrame`/`pushFrame`, `updatePersistentMesh`/`getPersistentMesh`, `unrollMesh`, `getAnchorCandidates`, `getSplatCount`/`getImmutableSplatCount`, `setSplatsVisible`, `getConfidenceAvgs`, `getLastDepthTrace`/`getLastSplatTrace`. Each gate that depended on one was re-reasoned rather than blind-deleted; the load-bearing ones are the autosave and `mapGrew` fixes above.
- [x] **The map thread and its frame queue.** `mapThreadFunc` drained a queue that `pushFrame` (a no-op) never filled. ✅ thread, queue, mutex and condvar removed; `destroy()` no longer joins a thread that does nothing.
- [x] **Per-frame CPU burned into a no-op.** `nativeFeedArCoreDepth` ran a full per-pixel depth decode over every ARCore depth frame and `nativeFeedStereoData` ran full stereo block matching, both ending in `pushFrame`. ✅ both removed, with their Kotlin callers.
- [x] **The software-stereo path advertised depth it could not produce.** `StereoDepthProvider.submitFrame` (the only live producer) fed `feedStereoData`; its `isDualLensActive` flipped true as soon as its buffers allocated, which lit the "SW STEREO" diagnostic and the tap-to-distance gate on devices with no depth at all. ✅ `StereoDepthProvider` and `StereoProcessor` removed; `isDualLensActive` collapsed into `isHardwareStereoActive`, which is the only one that was ever real.
- [x] **`ArUiState.immutableSplatCount` / `visibleSplatConfidenceAvg` / `globalSplatConfidenceAvg`** — written every tracking tick from natively-hardcoded zeros, read by nothing. ✅ removed, along with the matching parameters on the tracking callback.
- [x] **The Liquify tool.** `prepareLiquify`/`applyLiquify`/`drawLiquify`/`bakeLiquify` had no caller; `ImageWarper::init()` was only reachable from `nativeInitGl`, which Kotlin never called, so its GL was never initialised either. ✅ the Kotlin wrappers, the JNI entry points and `ImageWarper` are gone.
- [x] **The `parallaxMinDegrees` setting** — a persisted DataStore preference whose only consumer was `setParallaxMinDegrees`, a native no-op, and which had no settings UI. ✅ the whole chain removed.

## Tooling

- [x] **`./gradlew detekt` had never worked.** The root build applies detekt to every project with `config.setFrom(files("$rootDir/config/detekt/detekt.yml"))` and that file was not in the repository, so every module's task failed with "Configuration file … does not exist" — while `docs/contributing.md` asks every contributor to run it before submitting. ✅ `config/detekt/detekt.yml` added and the tree brought to zero findings under it. The config is deliberately shaped to catch defects rather than to relitigate structure: the size/complexity rules are off with a written reason (ArRenderer's frame loop and MainActivity's `onCreate` genuinely are large, and a gate that fires on them every run just teaches people to ignore it), while `SwallowedException`, `UnusedPrivateMember`/`Property`, `UnsafeCast`, `UnreachableCode` and friends are on and clean. Getting there fixed 29 files with no trailing newline, bound 30 deliberately-inert catch clauses as `_` so the intent is stated at the catch site, made `AzpInstaller` carry the manifest parse failure as a cause instead of only its message, and surfaced most of the dead members listed above.

## Still open

- [ ] **AR-glasses calibration is a stub.** `ArViewModel.glassesWorldHitForTimestamp` hit-tests the same phone screen point for src and dst, so Procrustes always returns identity; the solve degenerates on coplanar taps; `applyPhoneToGlasses` has no consumer; there is no UI entry point. Finishing it needs a real glasses-side world lookup — new native/SDK integration, not a squash. Retained (isolated, no runtime cost, unreachable so it cannot mislead).
- [x] **AR freeze-preview — resolved, was mistaken identity.** `onFreezeRequested` / `FreezePreviewScreen` / `unfreezeRequested` was not an unshipped "hold the design still" feature; it was an unused diagnostic screen (ORB feature blobs + a depth-warning banner) for reviewing target-capture quality, with no caller anywhere. The real "hold the design still" feature is Trace mode's Freeze — the per-mode transform lock (`isTransformLocked`), already shipped and escapable via Volume Up/Down/Up/Down. Deleted the diagnostic chain rather than wiring it up.
- [ ] **Bidirectional co-op.** Guests can receive but not transmit. The drop is now stated rather than silent (above); building a guest→host DELTA channel is feature work, and which app owns co-op after the GraffitiXR/GraphiXR split should decide it first.
- [ ] **Smaller unreferenced members**, each harmless and each wanting a per-item decision rather than a sweep: `SlamManager.setRelocEnabled` / `getMapPointCount` / `hasCorroborationMeasurement` / `setWallPatch` / `annotateKeypoints` (diagnostic and eval knobs with live native implementations), `ExtensionRepository.revokedInstalled` (the revocation feed has no UI yet), and a handful of unused helpers in `feature/ar` (`beginPlaneRealignment`, `confirmTapCapture`, `setVisualizationHidden`, `startRegistration`) and `core/common/util` (`rotateBitmap`, `saveBitmapToCache`, `resizeBitmapForArCore`). `setStageEnabled` is **not** in this "live implementation" bucket: `MobileGS::mStageEnabled` was written but never read, so toggling it did nothing while `getStageTimingsAndReset` structurally reported 0.0 for 4 of its 5 stage slots (0-3 name a splat-rendering pipeline this engine never implemented — only stage 4, pnpReloc, is actually timed). Fixed: `setStageEnabled` is now a documented, logged no-op instead of a silent one, `mStageEnabled` is removed, and `getStageTimingsAndReset` reports `-1.0f` ("not measured") for indices 0-3 instead of a fabricated `0.0`. Any consumer of `getStageTimings()` (currently `ArRenderer.kt`'s `DriftCostProbe` wiring, `EvalSampleLog`'s CSV columns) that assumed all 5 slots were real per-stage costs needs to treat `-1` as "not measured" for those four columns — flagged here as a caller-side follow-up outside this file's scope.
