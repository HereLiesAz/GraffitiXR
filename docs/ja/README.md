# GraffitiXR

GraffitiXRはストリートアーティストのためのAndroidアプリです。カメラビューに画像をオーバーレイして仮想的にトレースできるアプリはたくさんありますが、スマートフォンに保存したスケッチをもとに壁画を描くとき、三脚を使うのは作業の流れを大きく妨げます。私たちはあちこち動き回るものです。私自身は、スマートフォンをポケットに入れます。ARを使って画像を安定して一箇所に保持するアプリでさえ、ポケットの中の絶望的な暗闇には対処できません。

そこで、（知る人ぞ知る）グリッド法を再利用して、もっと良いものを作ることにしました。私はずっと、「これらの特定の落書きを、永続的なアンカーのように保存できないだろうか。そうすればオーバーレイは常にちょうど正しい場所にあるはずだ」と考えていました。

それで今、その落書きがまさにその役割を果たしています。

クラウドの助けを借りずにAndroid上で動作するカスタムの**フィンガープリント式リローカライザー**を発明する必要がありました——なぜなら、グラフィティは、ご存じの通り違法だからです。壁にロックオンすると、アプリはあなたの描いたマークのOpenCV特徴量による**フィンガープリント**（記述子と少数の三角測量された3D点）を取得します。トラッキングを失った後や画面オフの後でも、エンジンはライブカメラ映像をそのフィンガープリントと照合し、姿勢（PnP）を解いて数ミリ秒で**スナップバック**し、壁画を壁に再整列させます——クラウド不要、部屋全体の事前スキャンも不要です。

そして、私が**目的論的SLAM（Teleological SLAM）**と呼ぶものでこれを補完しました——結果がどうなるべきかを知っているので、OpenCVを使って進捗を確認し、進めば進むほどオーバーレイが壁にしっかりと貼り付くようにしています。これがなければ、絵そのものでマークを覆い隠してしまい、進むにつれてアプリの精度が落ちていきます。これこそ、この種の他のアプリが本当に失敗するところです。

このスナップバックと自己拡張フィンガープリントの両方は、現在オプトインのトグル（設定 > 診断オーバーレイ、デフォルトはオフ）として提供されており、実機での検証を進めている段階です。そのため、現時点ではどちらも標準では有効になっていません。

ちなみに、他のアプリと同じように画像トレース用の非AR画像オーバーレイ機能も含めています。そういうのが好きな方のために。あるいは、もっとこだわりたいなら**モックアップモード**があります。壁の写真を撮れば、手早くモックアップを作るためのツールが使えます。そして、証明することは何もなく、ただ何かを紙に完璧にコピーしたいだけなら、**トレースモード**でスマートフォンをライトボックスとして使えます。画面を最大輝度でオンにしたまま、画像を所定の位置にロックし、完了するまですべてのタッチをブロックします。

さらに、配置する一枚の画像を準備するための、それなりのデザインツール一式もあります——トーン、カラーバランス、輪郭抽出、被写体の切り抜き。複数の画像を1つに合成する作業は、このアプリではなく姉妹デザインアプリの仕事です。まだまだ話せますが、もう十分話したと思います。

## 主な機能
*   **オフラインファースト:** アプリが行うあらゆる処理にクラウド依存はありません——トラッキング、レンダリング、デザイン作業はすべてローカルで行われます。デバイスから出ていく唯一の情報はクラッシュレポートで、それはオプトインかつデフォルトでオフです（設定 > クラッシュレポート）。詳細は[`docs/ja/PRIVACY_POLICY.md`](PRIVACY_POLICY.md)を参照してください。
*   **フィンガープリント・リローカリゼーション:** C++17のネイティブOpenCVパイプライン（ORB/SuperPoint記述子 + PnP/RANSAC）が、壁に描いたマークをフィンガープリント化し、トラッキング喪失後にオーバーレイをスナップバックさせます——完全にオフラインで、部屋の事前スキャンも不要です。
*   **ポケット対応（実験的、デフォルトでオフ）:** ドリフト補正と自己拡張フィンガープリント（元の参照マークが塗りつぶされてもスナップバックが機能し続けるようにする機能）が存在し、設定 > 診断オーバーレイからオンにできますが、どちらもまだ実機で検証されていません——[目的論的SLAM](../TELEOLOGICAL_SLAM.md)を参照してください。
*   **デュアルレンズ対応:** ハードウェアのステレオ深度に対応したデバイスでは自動的にそれを選択します。それ以外のデバイスでは、別個の深度推定なしにARCoreの単眼姿勢でトラッキングします。
*   **共同作業モード（Co-op Mode）:** 暗号化されたQRペアリングによるセッション共有で、コラボレーターがホストのライブキャンバスをARで見られます。現在はホスト→ゲストの一方向のみです——ゲスト自身の編集はまだホスト側に同期されません。
*   **AzNavRail UI:** スプレー缶を持つアーティストのために設計された、親指操作の片手用ナビゲーション。

## モード
*   **AR壁画:** 上記のフィンガープリント・リローカライザーによってトラッキングされ、デジタルコンセプトを物理的な表面に固定するための中核的な精密ツールです。
*   **モックアップモード:** 静止した壁の写真の上でレイヤーやブレンドモードを可視化するための、手早いツール群です。
*   **トレース（ライトボックス）:** タッチロック、レール自動収納、物理音量ボタンによる終了（上、下、上、下）を備えた、紙にトレースするための最大輝度の表示面です。
*   **オーバーレイ:** 非ARの画像トレースです——参照画像がライブカメラ（CameraX）に重ねて表示され、不透明度を調整できます。ARCoreが利用できない少数のデバイスでは、代わりに同じOpenCVパイプラインを使って壁にマークした形状をトラッキングできます（平面限定）。
*   **デザイン:** トレース対象の一枚のデザイン画像のための配置・視認性ツールです——不透明度/明るさ/コントラスト/彩度/カラーバランス、反転、輪郭抽出、被写体の切り抜き。デザイン画像はちょうど1枚のみです。複数の画像を1つに合成する作業は、このアプリではなく姉妹デザインアプリの仕事です。

## アーキテクチャ
厳密に疎結合されたマルチモジュールのクリーンアーキテクチャです。
*   `:app` — ナビゲーション、カメラのオーケストレーション、Hiltによる依存性注入。
*   `:feature:ar` — ARCoreセッション管理、`ArRenderer`、SLAMデータ処理。
*   `:feature:editor` — 単一のデザイン画像の操作と調整。
*   `:feature:dashboard` — プロジェクトライブラリ、オンボーディング、設定。
*   `:core:nativebridge` — ネイティブC++エンジン（`MobileGS`）、JNIブリッジ、リローカリゼーションスレッド。OpenCV自体はMaven Centralの依存関係（`org.opencv:opencv`）であり、バンドル済み（vendored）モジュールではありません。
*   `:android_collaboration_module` — 共同作業モードのためのピアツーピア通信（ホスト→ゲスト、上記「主な機能」を参照）。
*   `:core:data` / `:core:domain` / `:core:common` — 統一されたデータ層とウェアラブル抽象化層。
*   `:core:design` — 共有のCompose デザインシステム（再利用可能なコントロールとオーバーレイ）。
